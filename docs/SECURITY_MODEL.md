# 权限与安全模型

Aa Browser 将网页、桌面外壳、MCP 客户端与任务调度分开处理。隔离和审批减少意外操作，不是能识别所有秘密的通用 DLP，也不把恶意本机程序变成安全程序。

## 权限与审批

| 权限级别 | 作用 |
| --- | --- |
| `browse` | 普通页面浏览 |
| `read` | 普通页面读取 |
| `interact` | 普通页面交互；高危对象仍需单独审批 |
| `files` | 受策略约束的文件访问 |
| `network` | 网络监控或环境操作 |
| `sensitive` | Cookie、Storage、凭据与未脱敏数据等敏感读取 |
| `high-risk` | 支付、删除、发布、提交等高危操作 |

权限范围包含 Profile，并可进一步限定客户端与任务。授权有期限、可以撤销；高危与敏感授权还必须绑定准确的操作名称，始终单次消费。范围授权无法说明具体 DOM 对象或脚本，因此只用于范围记录与审计；具体高危或敏感操作仍需原生人工审批。普通浏览、读取、交互是默认基础能力，不代表可以绕过敏感字段检测、站点白名单和高危操作审查。

高危页面操作审批默认勾选「本会话内相同操作自动允许」：用户第一次允许时，只有同一 Profile、同一 MCP 客户端、同一页面、同一元素指纹（或同一段脚本/同一文件）的同类操作会在本次浏览器会话内直接放行；不同目标、不同脚本、拒绝过的操作仍会重新询问。该记忆只存在于内存，退出应用即清空。敏感输入、网站设备权限以及 Profile/工作流等范围授权不参与自动放行。

`browser_permissions request` 只发起人工申请；MCP 调用者不能通过 `approved:true`、`once:false` 或 `requiresApproval:false` 给自己签发高危授权。浏览器原生审批必须由人处理，超时按拒绝处理。网站摄像头、麦克风、定位和通知权限按 Session/origin 与页面生命周期检查，不在 Profile 之间共享。

统一入口结合工具、动作与页面对象判断风险。网站文本和 DOM 无法完全表达所有业务含义；支付或发布之类的重要操作仍应由用户确认真实对象和结果。Agent 能看到已授权的页面正文，页面上的提示注入也不会自动变成用户授权。

## 身份和任务边界

每个持久化 Profile 对应独立 Chromium Session。客户端有自己的标签所有权和默认 Profile；工作流额外持有该 Profile 的租约，避免其他 Agent 调用插入执行。人工网页操作仍可改变页面，恢复时必须重新检查。

MCP 本地服务只监听 `127.0.0.1`，使用每次启动随机 token，发现文件包含端口、token、进程和版本。POSIX 文件请求 owner-only 权限；Windows 依赖当前用户目录权限。拿到发现文件的本机程序可能取得同等 MCP 控制能力，不应共享该文件或把它加入仓库。

任务与工作流按 MCP 桥会话过滤；重启后不能把循环使用的数字客户端 ID 当作历史任务的所有权证明。

MCP 工作流执行与检查点核验同时要求客户端所有者在线。客户端断开会暂停任务；重启后失联任务不能自动以桌面权限继续。桌面接管必须另行通过原生审批，而且只对本次调度有效；写入步骤仍需自己的审批和当前页面核验。

## 秘密与审计

日志和界面操作摘要对常见认证头、密码、token、Cookie、私钥与敏感 URL 参数做脱敏。网络详情与 HAR 默认脱敏；请求正文和响应正文也进行内容处理与大小限制。脱敏依靠可识别的字段和模式，无法保证任意图片或任意无标签文本都已删除所有秘密。

敏感输入字段继续由用户亲自填写。工作流实际输入整体通过操作系统安全存储加密后持久化；安全存储不可用时只保存在当前进程，重启必须重新输入。审计中的工具结果只保留元数据，不存页面正文或图片内容。

代理密码仅接受操作系统安全存储，不支持时拒绝保存，不回退明文。认证仅对指定 Profile 当前配置的代理主机与端口生效，网站服务器认证不能拿到代理密码。SOCKS5 用户名/密码认证以及带认证的按网站代理规则不受支持。

## 文件访问与证据

文件策略要求绝对路径，检查 Profile 管理目录与已批准的外部访问，拒绝其他 Profile 私有目录、符号链接与目录 junction。Windows 另外拒绝设备路径、备用数据流和保留文件名。导出默认拒绝覆盖，临时文件用排他创建和原子替换；上传只允许普通文件。

截图、HAR、PDF 和基线本身可能含页面秘密。不要把真实账号页面截图、HAR、Profile 归档或下载文件提交到 Git；共享排障信息前人工检查。证据治理记录文件散列、大小和有效期，不等于内容脱敏。

Profile 归档使用至少 12 字符的密码、scrypt 与 AES-256-GCM。完整归档只允许本进程未初始化的离线身份，不复制正在写入的 Chromium 数据库。导入生成新目录并校验每个相对路径，默认身份采用整体离线备份。见 [Profile 指南](PROFILES.md)。

## 恢复与修复

工作流先保存调度意图，再执行工具。已完成步骤不会因重启而重放；可能产生副作用的中断步骤进入等待核验与人工审批。幂等账本独立于任务历史，历史损坏不能使旧高危请求重新执行；账本损坏或不可写会拒绝相关写操作。

诊断修复是明确操作，不是后台随意清理：刷新可能丢失未提交表单，重新连接会关闭在途连接，缓存清理仅清理 HTTP 缓存。Cookie、网站存储、登录态和重要文件不会被默认自动删除。

## 发行与报告

安装器核验发行摘要和文件类型，更新路径保留旧版兼容的更新元数据。摘要、SBOM 或 GitHub 发行证明不等于 Windows Authenticode 签名；没有配置签名证书时安装包仍未签名，不能宣称已完成代码签名。正式签名需维护者提供可用证书及受保护的 CI 签名配置，再验证签名与升级路径。

安全漏洞请遵循根目录 [SECURITY.md](../SECURITY.md) 私密报告，不在公开 issue 中附带可用凭据、HAR 或账号数据。
