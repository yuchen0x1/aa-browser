# v0.0.4 发布与更新验证

## 1. 总览

2026-11-13，本地安装版核实为 0.0.2。其 GitHub 更新配置能够发现 0.0.3，但自动下载关闭，且更新状态只在设置内可见；程序持续打开时原有周期检查间隔为 6 小时。

v0.0.4 增加主界面提示、后台下载和失败重试。针对本地 NSIS/目录包重复运行暴露面扫描，观察到 80 个外部文件、7 个原生二进制和 4 个外部脚本，原始启发式分数仍为 16/100、D。此分数包含公开依赖/本地通信和已排除的误报，不作为产品安全评分。

## 2. 发现清单

| 编号 | 判定 |
|---|---|
| 更新可见性 | 已修复：主界面提示、工具栏入口、下载进度与待安装提示 |
| 自动下载关闭 | 已调整：自动更新开启时后台下载，安装仍由用户主动触发 |
| 失败恢复 | 已修复：检查/下载区分重试，1/5/15 分钟退避，恢复事件按需补查 |
| 签名/fuse/依赖 map | 沿用 v0.0.3 的已知限制，详见对应审计报告；本次未引入签名证书或新的运行模式 |

## 3. 证据与处理

- 读取实际安装包 package.json 和本机发现文件，均为 0.0.2；仅查看配置与版本，没有修改旧客户端或其登录数据。
- 使用安装版相同公开更新配置、真实 Electron 网络栈及真实 electron-updater，隔离模拟当前版本为 0.0.2，确实发现 0.0.3。
- 将本次编译出的生产 UpdateManager 接到真实 NsisUpdater，在仓库内独立 profile/cache 中自动发现并下载公开的 0.0.3 安装包，收到 `downloaded` 和 `noticeVisible:true`。文件由原生更新库执行元数据完整性检查；该试验没有运行安装器。
- 91 项 MCP、18 项桌面回归、12 项更新状态和 5 项更新 UI 检查通过；后两组使用模拟 provider，明确与上面的真实网络试验区分。类型、构建、8 项持久化及 4 项发布脚本检查通过。
- 本地 v0.0.4 NSIS 安装包和 latest.yml 的大小、SHA-512 一致。完整暴露面扫描仍存在依赖 map、解包脚本、第三方 DLL/PDB 和签名限制；本项目公开源码不以混淆隐藏代码为安全边界。

## 4. 客户端无法解决的问题

发布新版本不能把代码自动注入正在运行的 0.0.2。首次仍需通过旧版设置或安装包升级，新逻辑才会生效。真实旧版发现、下载、安装、重启应逐步记录，不能将模拟状态或真实下载称作完成安装。

安装包仍未签名；内容哈希校验不替代发布者签名或可信分发渠道。自动安装未启用，避免未经用户选择就关闭页面。

## 5. 顺序与后续

先修复并回归客户端提示/下载，再发布完整更新资产；随后在用户允许的时机执行首次安装并核对本机版本。未来需要完善签名、跨进程数据合并和跨机器更新验收。详细静态暴露证据与误报判定沿用 [v0.0.3 报告](./RELEASE_AUDIT-v0.0.3.md)。
