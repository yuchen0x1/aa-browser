# GitHub Releases 更新模板（逐版本通用）

> 每次发布只填写当前版本。先依据实际代码变更、提交记录和测试结果整理内容，再复制「Release Notes 正文」到 GitHub Release。方括号内容是待填写项；发布前删除占位文字及不适用栏目。

## 一、Release 标题（填写在 GitHub Title 栏）

格式：

`[项目名称] v[版本号]`

示例：

`Aa Browser v0.3.0`

标题只填写在 GitHub 的 Title 栏。正文不要重复项目名称、版本号或另加一级标题。

## 三、版本号与内容范围

- **修订版（PATCH，例如 `0.2.1`）**：通常用于兼容性修复、安全修复和小范围缺陷修复。若包含破坏性变化，必须在概述和升级说明中明确标出。
- **次版本（MINOR，例如 `0.3.0`）**：通常用于向后兼容的新功能和改进；说明新增能力及其使用方式。
- **主版本（MAJOR，例如 `1.0.0`）**：可能包含不兼容变化；必须列出受影响功能、迁移步骤、数据处理方式和回退限制。
- **预发布版本（例如 `1.0.0-beta.1`）**：明确标注测试性质、尚未完成的内容、适用人群及升级到正式版的注意事项。

## 四、发布前核对（不要复制到正文）

1. 标题中的项目名称和版本号与标签、安装包及更新元数据一致。
2. 正文只记录本次版本实际交付的变更；每条都能追溯到代码、提交、Issue 或测试证据。
3. 不编造功能、修复、性能收益、兼容平台或测试结果；没有基准数据时不宣称“更快”或“降低资源占用”。
4. 下载表中的文件名、平台、架构和类型与本次上传的 Release Assets 完全一致。
5. 明确说明不兼容变化、配置或数据迁移、签名状态和已知限制；不适用的栏目直接删除。
6. 删除所有方括号占位符、空标题、示例内容和内部发布备注。
7. 正文以「📢 版本概述」开始，不重复 Release 标题；Markdown 表格及链接可正常显示。
8. 使用简体中文撰写；产品名、命令、API、文件名等技术标识保留原文。
