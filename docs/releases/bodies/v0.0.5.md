## 📢 版本概述

本版让全部 33 个 MCP 工具在 `tools/list` 中声明只读、破坏性、幂等与开放世界四类风险提示，AI 客户端可以在调用前给出更准确的风险说明，也减少因缺少元数据而直接拒绝工具的情况。客户端接入不再启动子进程探测系统 Node，改为查找 `PATH` 并在缺失时回退到应用自带运行时。Windows 安装包仍未配置代码签名，首次安装时 SmartScreen 可能提示确认。

## ✨ 新增功能

- **MCP 工具风险标注**：此前工具描述里没有机器可读的风险字段，客户端难以判断一次调用是否写数据或改动站点 → 本版为 33 个工具逐一显式声明 `readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint` → 适用于所有 MCP 客户端，无需额外配置，调用前的风险提示由客户端自行渲染。

## 🔧 改进与优化

- **工具清单一致性**：本版把主进程、MCP 桥与 README 的工具清单统一，并新增 `scripts/test-tool-contract.mjs` 静态契约测试 → 后续任何工具漏声明四类提示或桥与主进程不一致都会直接失败 → 减少客户端看不到工具或调用失败的情况。
- **客户端接入探测**：此前执行 `spawnSync('node', ['--version'])` 起子进程判断系统 Node → 现在按 `PATH` 直接查找 `node` / `node.exe`，不经过 shell、不启动探测进程 → 接入结果不再受 shell 环境与子进程权限影响；找不到系统 Node 时仍回退到应用自带的 Electron 运行时。

## 🔒 安全与兼容性

- **Windows 安装包仍未签名**：首次安装或覆盖升级可能触发 SmartScreen 未识别发布者提示；确认来源后选「更多信息 → 仍要运行」。代码签名与首次信任建立尚未验收。
- **写入客户端的 MCP 命令**：从裸 `node` 改为解析后的绝对路径（或应用自带运行时）。已有配置在系统 Node 可用时仍能启动；如需固定到具体运行时，重新执行一次客户端写入即可。

- 已安装用户：支持应用内更新，在「设置 → 软件更新」检查并下载，下载完成后确认重启安装。

## 🔄 升级与数据迁移

- **兼容性**：Windows x64 单一平台、NSIS 安装包，可直接覆盖安装；本版没有配置格式或平台变化。
- **配置和数据**：设置、历史与站点数据保存在 Electron 用户数据目录（`%APPDATA%\Aa Browser`）的配置文件与 Chromium profile 中，覆盖安装沿用同一应用标识，通常无需迁移；升级前建议备份用户数据。
- **回退方式**：可以从 Releases 重新安装旧版官方安装器；退回前建议暂停自动检查并备份用户数据，已登录会话可能受 Chromium 跨版本格式约束。

## 🧪 验证结果

- 冒烟测试：断言 `tools/list` 返回 33 个工具、每个工具都带四类风险提示，并实际调用 `browser_press_key` 与 `browser_console`（覆盖范围见本版发布说明）。
- 工具契约测试：`scripts/test-tool-contract.mjs`（`npm run test:tools`）要求主进程与 stdio 桥的工具名及四类提示取值完全一致，并禁止客户端接入代码再出现 `spawnSync` / `node:child_process`。
- 真实旧版安装、重启、在线升级与代码签名：未验证（本版发布说明明确不以模拟测试代替用户电脑上的安装证据）。

## ⚠️ 已知问题

- Windows 安装包未代码签名，SmartScreen 会提示未识别发布者；影响首次安装与覆盖升级，按上文选择「仍要运行」。
- Agent 能看到页面内容与网络流量，包括可能含秘密的 Cookie、Storage、请求头和响应体；这些措施不是通用 DLP，不要让不可信 Agent 访问高敏站点。
- 普通标签默认共享登录态，需要隔离时在设置中启用隔离会话。
