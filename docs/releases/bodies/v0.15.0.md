## 📢 版本概述

Aa Browser v0.15.0 adds bounded renderer recovery and a strict, auditable task lifecycle for MCP calls. This release ships Windows x64 assets only; Linux is temporarily held back after a Linux desktop regression failed in release CI. Existing browser and MCP interfaces remain compatible.

## 一、核心变更

- Renderer/WebContents crash and unresponsive events now expose `healthy`, `recovering`, `recovered`, and `failed` states, with the triggering event recorded as the recovery reason.
- Recovery reloads are bounded to two attempts, preserve the current tab URL/session, and clear timers when a tab closes.
- The new `TaskCenter` exposes `pending`, `running`, `waiting`, `paused`, `interrupted`, `recovering`, `completed`, `failed`, and `cancelled` states for auditable orchestration.
- Destructive task recovery is confirmation-gated and every transition records a bounded history with reasons and retry counters.

## 二、兼容性与安全

- `TabInfo.recovery` is optional, so older MCP clients can continue to consume tab listings.
- A failed or interrupted operation is not silently reported as completed and is not retried indefinitely.
- No credentials, cookies, or tokens are added to task history.

## 三、验证与限制

- The release workflow runs type checking, linting, Windows Electron tests, Windows packaging, SBOM generation, update metadata validation, and asset digest verification; the Windows desktop suite and installer smoke passed in release CI.
- Real renderer-crash recovery and Windows code signing remain unverified in this release. The Windows package is unsigned; SmartScreen may warn during installation.
- Linux packaging and Linux desktop validation are intentionally excluded from v0.15.0 and will return in a later version after the regression is resolved.
