## 📢 版本概述

v0.18.2 修正高危操作审批面板的显示位置：面板改为顶部居中，说明文字独立滚动，拒绝/允许按钮始终可见，不再被面板底部裁切。新增「本会话内相同操作自动允许」，同一页面、同一操作确认一次后，本次浏览会话内不再重复弹窗；新操作、敏感输入和网站权限仍逐次确认。浏览器数据格式与更新机制保持兼容。

## ✨ 新增功能

- **本会话内相同操作自动允许**：高危操作审批面板新增默认勾选的记忆选项。第一次点「允许」后，只有同一 Profile、同一 MCP 客户端、同一页面和同一元素指纹（或同一段 JavaScript / 同一文件）的同类操作会在本次浏览器会话内直接放行。记忆只保存在内存中，退出应用即清空；不同目标、不同脚本和拒绝过的操作仍会重新询问。

## 🔧 改进与优化

- **审批面板布局**：面板从右上角改为页面保留区顶部居中，宽度随窗口自适应；标题、站点信息和操作说明放在可滚动区域，底部操作栏固定，长说明不再把按钮挤出可视区。
- **多请求排队显示**：同时有多个待确认请求时逐条显示，并提示「待确认 1 / N」，处理完自动显示下一条；队列中的后续请求不会自动抢焦点，避免持续按 Enter 时误批准下一条高危操作。
- **布局常量统一**：工具栏、更新提示条、查找条和审批预留带的高度改由共享常量维护，主进程的原生视图尺寸、页面偏移和外壳 CSS 使用同一组数值。

## 🐛 问题修复

- **审批按钮被裁切**：修复面板整体使用固定最大高度和滚动条时，底部「拒绝 / 允许」只露出一半、必须先在面板内滚动才能点击的问题。
- **面板遮挡与位置漂移**：更新提示条或查找条显示时，审批面板会跟随预留区下移并保持居中，不再贴在右侧边缘。

## 🔒 安全与兼容性

- 自动放行严格限定在同一 Profile、同一 MCP 客户端、同一页面及同一目标/脚本；Profile、工作流、诊断修复等范围授权不参与记忆，仍保持逐次人工确认。
- 敏感输入、网站摄像头/麦克风/定位/通知权限始终逐次处理，不会被本会话记忆放行；中断期间拒绝的请求或迟到的「允许」不会生成会话授权。
- 不改变浏览器用户数据、Profile、设置、MCP 配置或更新源格式。

| `latest.yml` | Windows x64 | 稳定版更新元数据 |

- 已安装用户：在「设置 → 软件更新」检查并按提示下载、确认重启安装；已安装的 v0.18.x 会通过现有更新源收到本版本提示，关闭自动检查的用户可手动检查。

## 🔄 升级与数据迁移

- **兼容性**：沿用现有应用标识、安装方式和稳定更新源，可直接覆盖升级。
- **配置和数据**：浏览器个人数据、登录态、Profile、设置和 MCP 配置格式均不变，不需要迁移。
- **回退方式**：回退前先关闭应用并备份 `.aabrowser` 与 Electron userData；旧版本无法管理新版本之后创建的数据格式。

## ⚠️ 已知问题

- Windows 安装包没有 Authenticode 签名，可能出现 SmartScreen 提示；Linux 验证范围限 Ubuntu 24.04 CI/Xvfb，不代表所有发行版或物理多显示器。
- 同一元素或同一脚本的自动放行只在当前应用进程内有效；重启应用、重新连接 MCP 客户端或页面重新加载后需要重新确认一次。
- 说明文字特别长时仍需在面板内滚动查看，但拒绝/允许按钮始终固定在底部。
