## 📢 版本概述

本版修正 MCP 导航对重定向与加载失败的判定：跟随 302 跳转后返回最终地址与落地页快照，主文档连接中断等真实失败明确报错，不再静默返回成功。同时修复新标签首个页面后退时回到空白页、关闭设置后未保存的语言预览仍然生效，并补齐英文界面里的自定义搜索地址与自动更新等文案。已安装用户可直接在应用内更新；Windows 安装包仍未配置代码签名。

## 🔧 改进与优化

- **英文设置文案补齐**：此前英文界面里「自定义地址」、自动更新与更新通道等控件和提示仍是中文或缺失 → 现在补齐默认搜索引擎、自定义地址、隔离会话与白名单提示、下载目录占位符、更新提示与客户端写入提示等文案，并作用到占位符与提示位置 → 英文用户可以完整理解连接与更新选项。

## 🐛 问题修复

- **MCP 导航误判**：此前导航用固定超时加地址前缀比较判断结果，302 跳转会被判成「未到达目标」，主文档连接中断也可能返回成功 → 现在以 WebContents 的实际结果为准：重定向返回最终网址与落地页快照，加载失败（如 `ERR_EMPTY_RESPONSE`）抛出明确错误。
- **新标签后退回到空白页**：新标签要先加载 `about:blank` 建立渲染上下文与 CDP 守卫，这条历史项一直留在记录首位 → 现在首个页面加载完成后移除该初始化历史项（仅当当前条目不在索引 0、且首项确为 `about:blank`）→ 后退从实际访问的页面开始。
- **关闭设置后语言预览仍生效**：此前在设置里切换语言后直接关闭，未保存的预览会一直留在界面上 → 现在关闭设置即恢复已保存的语言，保存成功后新语言才成为当前语言并在重启后继续使用。

## 🔒 安全与兼容性

- **导航结果的语义变化**：`browser_navigate` 在加载失败时改为返回错误而不是成功结果；调用方如果原先默认「返回即到达目标」，需要按错误分支处理。
- **安全边界不变**：非 HTTP(S) 导航仍被拒绝，GitHub Release 安装器仍要求有效 SHA-256 digest，高危审批仍覆盖未脱敏网络数据的查看与导出。
- **Windows 安装包仍未签名**：SmartScreen 可能提示未识别发布者，确认来源后选「更多信息 → 仍要运行」。

## 🔄 升级与数据迁移

- **兼容性**：Windows x64 单一平台、NSIS 安装包，可直接覆盖安装；本版没有配置结构变化。
- **配置和数据**：设置、历史与 Chromium profile 位置不变，覆盖安装后保留，已保存的语言选择继续生效；升级前建议备份用户数据。
- **回退方式**：可以从 Releases 重新安装旧版官方安装器；回退前建议暂停自动检查并备份用户数据，已登录会话可能受 Chromium 跨版本格式约束。

## ⚠️ 已知问题

- Windows 安装包未代码签名，SmartScreen 会提示未识别发布者；影响首次安装与覆盖升级。
- 导航失败现在统一报错（含主文档连接中断），调用方需按错误分支处理，不能沿用旧的「静默成功」判断。
- Agent 能看到页面内容与网络流量，包括可能含秘密的 Cookie、Storage、请求头和响应体；不要让不可信 Agent 访问高敏站点。
