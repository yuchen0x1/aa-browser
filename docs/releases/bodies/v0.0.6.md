## 📢 版本概述

本版集中收紧三处安全边界：外部导航只接受 HTTP(S)，GitHub Release 安装器在缺少有效 SHA-256 digest 时直接中止安装，开启高危审批后查看或导出未脱敏网络数据必须经用户确认；同时把 CI 的并发控制与仓库权限收紧为只读。这些变化会限制用本地文件协议打开页面、以及依赖旧版宽松校验的用法，升级前请先读「升级与数据迁移」。Windows 安装包仍未配置代码签名。

## 🔧 改进与优化

- **冒烟测试的测试页来源**：此前用 `file:///` 加载本地测试页 → 导航策略拒绝非 HTTP(S) 后改为由本地 HTTP fixture 提供同一测试页 → 冒烟仍覆盖完整 MCP 与桌面流程，且不再依赖被拒绝的协议。

## 🔒 安全与兼容性

- **非 HTTP(S) 协议导航被拒绝**：此前白名单为空时 `file:`、`data:`、`devtools:`、`view-source:` 等协议会被隐式放行 → 现在只允许 `http:` / `https:`，仅应用内部新标签页例外 → 影响：不能再用 Aa Browser 打开本地 HTML 文件或 `data:` 地址，需要本地页面时请起一个本地 HTTP 服务。
- **安装器 SHA-256 校验改为 fail-closed**：此前 Release 未提供 digest 时只做非空与 PE 文件头检查并告警 → 现在 `install.mjs --repo` 遇到缺失或格式错误的 `sha256:<64 位十六进制>` digest 一律中止安装 → 影响：自动安装要求资产带有效 digest，确需手动校验时用 `--sha256` 显式指定预期值。
- **敏感网络数据需人工确认**：此前开启高危审批后，`includeSensitive:true` 的 `browser_network_detail` 与 `browser_har` 仍直接返回未脱敏数据 → 现在先发起审批，用户拒绝或超时按拒绝处理 → 影响：Agent 在无人值守时拿不到认证头、凭据参数和未脱敏 HAR。
- **CI 权限与并发**：工作流新增按 `workflow` + `ref` 的并发组（`cancel-in-progress: false`），默认权限收紧为 `contents: read`，并新增安全回归作业步骤 → 影响范围是发布流水线，用户侧无需操作。

- 已安装用户：支持应用内更新，在「设置 → 软件更新」检查并下载，下载完成后确认重启安装。

## 🔄 升级与数据迁移

- **兼容性**：Windows x64 单一平台、NSIS 安装包，可直接覆盖安装；本版改变的是导航协议与安装器校验行为，不涉及配置结构。
- **配置和数据**：站点白名单、设置、历史与 Chromium profile 的位置不变，覆盖安装后保留；升级前建议备份用户数据。依赖「白名单为空即放行本地协议」的用法需要改走 HTTP(S)。
- **回退方式**：可从 Releases 重新安装旧版官方安装器；退回会恢复旧的协议放行与宽松 digest 行为，退回前建议暂停自动检查并备份用户数据。

## 🧪 验证结果

- 安全回归 `scripts/test-security.mjs`（本版新增并接入 CI）：用桩 `fetch` 断言 Release digest 缺失、格式错误时安装器以非零码退出并给出原因；显式 `--sha256` 格式错误同样中止。
- 桌面回归（本版新增断言）：开启高危审批后，`browser_network_detail` 的 `includeSensitive:true` 会等待审批，用户拒绝后返回「高危操作已取消」。
- 冒烟测试：改用本地 HTTP fixture 后继续验证完整 MCP 与桌面流程。
- 真实旧版安装、重启、回滚、线上更新与跨平台构建：未验证（本版发布说明明确仍需独立环境验证）。
- 代码签名与签名后的首次信任建立：未验证，Windows 仍缺 Authenticode 证书。

## ⚠️ 已知问题

- Windows 安装包未配置 Authenticode 代码签名，SmartScreen 可能提示未识别发布者；影响首次安装与覆盖升级。
- 拒绝非 HTTP(S) 导航后，本地 HTML 文件与 `data:` 页面无法在应用内打开，这是本版的策略限制而非临时故障。
- Agent 能看到页面内容与网络流量，包括可能含秘密的 Cookie、Storage、请求头和响应体；审批与脱敏是缓解手段，不是通用 DLP，不要让不可信 Agent 访问高敏站点。
