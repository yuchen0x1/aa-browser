# v0.16.0 runtime reliability slice

本文记录 v0.16.0 的核心运行时升级、数据格式、恢复边界和验证证据。历史 v0.15.0 的发布治理说明见 [`2026-11-24-v0.15.0-recovery.md`](./2026-11-24-v0.15.0-recovery.md)。

## 1. 任务持久化

### 存储选择

项目已有 `writeJsonAtomic()`（临时文件 + `fsync` + rename）和多个版本化 JSON 存储。本轮没有引入数据库，而是复用同一套约定：

- 默认文件：与 `connection.json` 同目录的 `task-center.json`（标准安装为 `~/.aabrowser/task-center.json`）
- 测试/隔离覆盖：`AA_BROWSER_TASK_CENTER_FILE`
- 格式：`{ version: 1, tasks: TaskRecord[] }`
- 上限：200 个任务；每个任务最多 200 条事件和 200 个步骤；错误文本截断到 240 字符
- 写入：创建、状态迁移、步骤、错误、删除和裁剪都会触发去抖持久化；终态与退出路径立即写入。临时文件替换遇到 Windows `EPERM`/`EACCES`/`EBUSY` 时做 10/25/50/100ms 有界重试，最终失败保留旧文件
- 损坏/版本处理：无法解析时保留 `task-center.json.corrupt-<timestamp>.bak`，未知版本保留 `task-center.json.unsupported-<timestamp>.bak`；本次从空表启动并记录诊断

### 任务记录字段

`TaskRecord` 持久化：

- 状态：`pending`、`running`、`waiting`、`paused`、`interrupted`、`recovering`、`completed`、`failed`、`cancelled`
- 开始/更新时间：`createdAt`、`updatedAt`
- 恢复：`retryCount`、`maxRetries`、`error`
- 执行：`history[]`（状态迁移审计）、`steps[]`（进度、渲染恢复和工具步骤）
- 上下文：`client`、`clientSession`、`clientName`、`source`、`callId`、`tool`、`instanceId`、`browserPid`、`tabId`、`rendererPid`、`startedAt`
- 未显式传 `tabId` 的活动标签调用会在工具开始前解析实际标签与 Renderer PID；渲染恢复尝试写入 `rendererRecovery` 上下文

`AgentTaskRecord` 保留原有 MCP/UI 字段，只新增可选字段：`taskId`、`tabId`、`source`、`updatedAt`、`retryCount`、`steps`。旧客户端不需要改动。

### 重启语义

1. 读取 `task-history.json` 和 `task-center.json`。
2. 任一存储中的 `pending` / `running` / `cancelling` / `waiting` / `paused` / `recovering` 记录在启动时转为 `interrupted`。
3. 写入原因 `上次进程未完成；任务未自动重放。` 或 `process_restart` 审计事件。
4. 不重新调用任何工具处理器；只读调用是否重发仍由 MCP 桥的 `RETRYABLE_TOOLS` 白名单决定。
5. 渲染恢复步骤由 `noteTabRecovery()` 追加到匹配 `tabId` 的进行中任务。
6. 若 `task-history.json` 缺失或损坏，`reconcileTaskCenter()` 会从有效 TaskCenter 的上下文重建 Agent 任务记录；历史写失败不再阻止 TaskCenter 终态立即落盘。

### 幂等终态

`finishTask()` 在任务已经处于 `completed` / `failed` / `cancelled` / `interrupted` 时直接返回。连接断开、暂停或取消先写入终态，迟到工具回调不能把它覆盖成另一种终态。暂停路径也通过 `finishTask()` 写入 TaskCenter，避免历史文件与任务中心分叉。

持久化主键为 `<client>:<callId>:<startedAt-base36>`，而不是仅用 MCP 请求 ID。桥、应用或 MCP 会话重启后请求 ID 会从 1 重新计数；加入启动时间后，新执行会创建新的 TaskRecord，旧终态记录只作为历史保留。若升级前遗留的 `client:callId` 记录仍与当前调用撞键，`finishTask()` 会核验并收敛到已落库终态，而不是把内存任务永久留在 `running` / `cancelling`；TaskCenter 记录缺失或状态机拒绝更新时，内存任务仍会完成并写入 `task-history.json`，同时记录诊断。

## 2. Renderer 崩溃恢复

- 真实注入：`webContents.forcefullyCrashRenderer()`，以及 Windows `taskkill /F` / POSIX `SIGKILL` 强杀真实 Renderer；不使用页面内假事件。
- 事件：真实 `render-process-gone`；原因接受 `crashed`、`killed`、`abnormal-exit`。
- 上限：`MAX_RECOVERY_ATTEMPTS = 2`，单次超时 15 秒。
- 标签身份、URL 和会话记录保留；新渲染进程没有任何旧 `window.__aaRefs`。
- 恢复中或恢复失败时，所有页面工具在 `onTab()` 入口返回 `RENDERER_CRASH`，而不是等待原生命令超时。
- 恢复加载期间再次崩溃会消耗下一次尝试并重新加载；不会忽略事件后空等 15 秒超时。
- 页面导航期间崩溃会让在途导航工具失败，但标签仍恢复为受支持 URL，并可重新获取快照。
- 已达到上限时返回 `已达到最大自动恢复次数`。
- `unresponsive` 仍由真实 Electron 事件触发；由于没有公开、确定性的无响应注入 API，本轮没有把忙循环测试纳入必过套件，也不声称已验证所有平台的无响应恢复。

## 3. Ref 代际

主进程为每个 `WebContents` 维护快照代际：

| 变化 | 失效原因 | 错误分类 |
| --- | --- | --- |
| 主框架开始导航、提交后 URL 漂移 | navigation changed | `NAVIGATION_ERROR` |
| 渲染进程重启 | renderer restarted | `RENDERER_CRASH` |
| 快照超过 30 分钟 | snapshot expired | `STALE_REF` |
| 元素从 DOM 移除 | element detached | `ELEMENT_NOT_FOUND` |
| 元素被隐藏或尺寸为 0 | not actionable | `OPERATION_REJECTED` |
| 跨域 iframe | frame unavailable | `FRAME_ERROR` |
| 标签关闭 | target closed | `TARGET_CLOSED` |

没有快照上下文时保持旧行为，首次操作不强制先调用 `browser_snapshot`。一旦存在快照上下文，旧 Ref 永远不会被自动映射到相似元素；错误信息直接要求重新获取快照。

## 4. Actionability 策略

在点击、输入、清空和下拉选择前检查：

- 元素存在且 `isConnected`
- 计算样式非 `display:none`、`visibility:hidden`、`opacity:0`
- 边界尺寸至少为 1×1
- 原生或 ARIA 禁用状态
- 输入目标可编辑，且不是只读
- `<select>` 本身启用，目标 `<option>` 未禁用
- iframe 坐标链可解析
- 点击前连续两次定位坐标稳定；持续移动的目标返回 `not-stable`，不派发点击
- 输入前焦点仍属于目标元素；焦点陷阱、inert 或页面抢焦点返回 `not-focusable`

命中测试失败仍允许页面内 DOM 事件兜底，但合成脚本返回 `detached` / `dispatch-failed` 时会明确失败，不会把未派发的事件报告为成功。后台控制不是屏幕坐标点击：视觉遮挡不等于 DOM 不可操作，因此保留该路径并在点击探针未确认送达时补发一次 DOM 事件。

## 5. 错误分类

`ActionError` 统一携带 `[CODE]` 前缀：

- `NAVIGATION_ERROR`
- `ELEMENT_NOT_FOUND`
- `STALE_REF`
- `TIMEOUT`
- `NETWORK_ERROR`（常见 Chromium 网络错误）
- `FRAME_ERROR`
- `TARGET_CLOSED`
- `RENDERER_CRASH`
- `MCP_CONNECTION_ERROR` / `PERMISSION_ERROR` 为后续传输层与权限层预留分类；本轮已实现的主要页面路径仍使用导航、元素、Ref、超时、Frame、Target、Renderer、网络、拒绝和任务冲突分类
- `OPERATION_REJECTED`
- `TASK_STATE_CONFLICT`

只读且幂等的工具可在连接恢复后重试；有副作用的工具不无条件重放。任务恢复有 `maxRetries`，每次迁移和失败原因进入 `history` / `steps`。

Node / 真实 WebSocket：

- `npm run test:task-center`：持久化、步骤、重启转换、损坏恢复。
- `npm run test:atomic-json`：Windows 短暂锁重试，以及持续失败时保留旧文件和清理临时文件。
- `npm run test:agent-cancellation`：TaskCenter 接线、活动标签/Renderer PID、TaskCenter-only 恢复、暂停持久化、断线后同会话查询、重试计数、多客户端冲突，以及桥重启后复用请求 ID 仍创建新持久任务的回归。

## 7. 边界

- Linux 仅在 `ubuntu-24.04` CI / Xvfb / AppImage 冒烟范围内验证，不代表所有发行版和桌面环境。
- Windows 安装包仍未 Authenticode 签名。
- 任务开始时记录 `rendererPid` 作为关联证据；Renderer 恢复后 PID 会变化，旧 PID 不再代表当前进程，恢复尝试另写入 `rendererRecovery` 上下文，UI/MCP 不把旧 PID 当成实时身份。
- 暂停是当前进程的安全闸门；暂停中的任务先记为 `interrupted` 并保留原因，重启后不会自动恢复旧暂停状态或接受未核验的重放。
- 进度步骤在 TaskCenter 内最多保留 200 条，但 `browser_tasks`/HUD 只携带最近 20 条以限制 IPC 开销；任务中心采用 1 秒去抖写入，终态立即写入。
- 真实 `unresponsive` 注入受平台和时序影响，未纳入必过门禁。
