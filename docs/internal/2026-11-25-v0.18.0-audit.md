# v0.18.0 implementation audit

Date: 2026-11-25. Baseline: `73d57a5`, package version 0.17.0.
This report was assembled before production code changes. Source inspection is
distinguished from executed tests; documentation alone is not acceptance evidence.

## Repository and architecture

The application uses Electron 45, TypeScript, electron-vite and a plain TypeScript
renderer. `src/main/index.ts` owns a BaseWindow, a privileged chrome WebContentsView,
and page WebContentsViews managed by `tabs.ts`. Only chrome has `preload/index.ts`;
web pages have context isolation and no Node integration. `snapshot/engine.js` and
`snapshot/scripts.ts` supply DOM/accessibility/ref operations injected by main.
`cli/mcp.mjs` implements stdio MCP and connects to a token authenticated loopback
WebSocket (`agent-server.ts`). `shared/tool-defs.mjs` is the schema source for all
47 existing tools and their annotations. `tools.ts` owns execution handlers.

Top-level directories: `.github` (CI/security/release), `build` (icons), `cli`
(bridge/setup), `docs` (user/internal/i18n/release documents), `installer`,
`packages/dsh`, `scripts` (regressions and publishing), `src` (main/preload/
renderer/shared/snapshot), and generated `out`, `release`, `node_modules` and
`.local-verification`. Dependencies and scripts were inspected in package.json,
package-lock.json, electron-builder.yml, electron.vite.config.ts and tsconfig.json.

## Engineering, release and documentation

CI runs Linux static/unit suites and Windows/Linux real Electron suites. Tag
publication additionally builds NSIS/AppImage, checks installation/uninstallation,
packaged MCP connectivity, main ancestry, version/assets/digests and creates an
SBOM. Release scripts and updater use the existing GitHub provider and stable
`latest.yml`/`latest-linux.yml`; these feeds and appId/data paths must be retained.
Signing hooks exist, but no signing success is inferred from configuration.

GitHub read-only checks on this date: zero open issues; no open Dependabot, code
scanning or secret scanning alerts returned. Seven dependency PRs need independent
review. npm audit against the npm registry reports zero vulnerabilities. Latest
published version is v0.17.0 with seven assets. Branch cleanup must preserve
unmerged work until ancestry or equivalent merged PR evidence is verified.

README, CONNECT, AUTO_UPDATE, PLATFORMS, SECURITY, CHANGELOG, internal architecture
and release documentation were inventoried. They describe the baseline, not the
new platform. New guides and delivery evidence must reflect tested behavior.

## Compatible implementation sequence

1. Preserve legacy default session; introduce validated Profile identifiers,
   independent persistent partitions, lifecycle metadata and context propagation.
   Make history/downloads/extensions/restoration Profile aware.
2. Close mandatory approval, sensitive-read/logging and file-boundary gaps; add
   centralized input validation and bounded execution. Preserve all 47 tool names.
3. Introduce a separate durable workflow engine reusing wrapped tool handlers;
   persist intent/checkpoints, stop on uncertain side effects, require fresh UI
   approval and page-state checks before mutation after recovery.
4. Apply actual Session proxy configuration with connection lifecycle handling;
   add bounded diagnostics and screenshot-bound visual operations. Clearly record
   unsupported OCR/model-dependent recognition rather than fabricate detection.
5. Bind desktop Profile/workflow/network/security/diagnostic panels to real state;
   retain existing navigation and native window behavior.
6. Run focused unit/integration tests, full existing checks, Windows desktop/UI,
   build and package checks; use Linux CI for Linux acceptance. Update real
   screenshots, user guides, architecture, migration and release evidence.
7. Publish v0.18.0 only after required checks pass; verify updater assets and old
   client compatibility. Report remaining limitations explicitly.
