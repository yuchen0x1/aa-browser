| P1 | 多次同时请求检查更新重复调用 provider | checking/downloading 状态拒绝重复检查 | 同时发起两次检查，provider 只被调用一次 |
| P1 | 已下载更新再次检查时变为 checking，待安装入口被覆盖 | downloaded 状态保留，检查按钮暂时禁用 | 模拟已下载事件后检查仍为 downloaded，不调用 provider |

主要修改：`src/main/atomic-json.ts`（新增）、`settings.ts`、`history.ts`、`tools.ts`、`updater.ts`、`index.ts`；外壳设置交互在 `src/renderer/src/chrome.ts`。没有新增依赖，没有修改现有 JSON 顶层格式。

读到异常文件时先在内存中恢复可用值，不立即改写原文件；实际修复保存发生时才保留异常原文并替换。历史写入失败保留旧文件和当前内存记录，并输出不含记录内容的提示。原子替换保证单次文件替换完整性，不代表具备跨进程锁或断电后所有目录元数据的持久性保障。

文件写入 API 按 [Node.js fs 文档](https://nodejs.org/api/fs.html) 核对；没有把目录包构建或模拟 provider 当成真实更新验收。

## 仍存在的不足

| 优先级 | 不足 | 当前证据与下一步 |
|---|---|---|
| P1 | 多进程的设置/历史合并 | 默认路径仍共享 `~/.aabrowser/`，Store 是各进程内缓存。开发版与安装版并行写入时存在最后写入覆盖风险；本轮未进行跨进程冲突复现，原子替换并不解决合并问题。需要文件锁/重读合并或显式分离开发数据路径 |
| P1 | 签名及真实升级验收 | 当前未配置签名证书；旧版发现→下载→安装→启动新版及失败恢复仍未验证 |
| P2 | 下载管理 | 只有下载跟踪、打开与定位；没有暂停/恢复/取消/重试和跨重启记录，系统打开文件失败也没有完整反馈 |
| P2 | 历史写入失败反馈 | 已保留文件并输出提示，但外壳还没有持久化告警入口，用户可能不知道新记录暂时只在内存中 |
| P2 | 浮层与键盘体验 | 当前浮层占用包含面板的顶部原生矩形，收起前部分网页点击区域被占用；还需覆盖多审批、读屏、DPI 与完整焦点恢复 |
| P2 | 书签/历史管理 | 当前历史主要用于地址栏建议，没有完整管理、批量删除/导出和书签组织入口 |
| P2 | 长时间资源与安全专项 | 无百标签、长下载、高频抓包的资源基准；本地 Agent 服务和各 MCP 工具的权限边界尚需专项审查 |

本轮没有复现出首轮页面查找、恢复、隔离和浮层已覆盖路径的新回归；这个结论仅限于列出的检查。
