## Что это

Обычные браузеры рассчитаны на человеческий глаз, который смотрит на пиксели; ИИ-агенту нужны **структурированные данные страницы**. Aa Browser — полноценный настольный браузер на Chromium (Electron), которым любой может пользоваться обычным образом — вкладки, адресная строка, история, загрузки, поиск по странице, сохранение сессий входа — и он открывает страницу любому агенту [MCP](https://modelcontextprotocol.io) через локальный stdio-мост: прочитать **структурированный снапшот доступности**, а затем кликать, вводить текст, выбирать, перетаскивать, прокручивать, извлекать данные и перехватывать трафик. Без скриншотов и без угадывания координат.

Снапшоты по умолчанию **инкрементальные**: неизменившаяся страница стоит одну строку, небольшие изменения возвращают только диф, а идентификаторы `ref` остаются стабильными между снапшотами. Мост слушает `127.0.0.1` с токеном, который создаётся при каждом запуске и хранится в `~/.aabrowser/connection.json`.

## Основные возможности

- 🖥️ **Настоящий браузер**: оболочка Electron/Chromium со вкладками, адресной строкой, кнопками назад/вперёд, поиском по странице, панелью загрузок и сохранением сессий входа.
- 🧠 **Структурированные снапшоты**: страница превращается в дерево доступности в стиле YAML, где каждый интерактивный элемент несёт идентификатор `ref` (`- button "Sign in" [ref=e5]`), в формате Playwright MCP.
- 💸 **Инкрементальные снапшоты экономят токены**: нет изменений → одна строка; небольшое изменение → только изменённые блоки; переход или крупные изменения → полный снапшот. На длинных задачах обычно экономится 60%+ контекста.
- 🎯 **Реальный путь ввода**: клики используют доверенные события ввода (`isTrusted=true`), ввод текста идёт через конвейер `insertText` с запасным путём для контролируемых полей React, а синтетические события покрывают редкий случай, когда реальное событие теряется.
- 🤖 **Нативная поддержка MCP**: стандартный stdio MCP-мост; им могут управлять Codex, ZCode, Claude Code, Cursor, Windsurf, Cline, VS Code, Gemini CLI, Qwen Code и WorkBuddy.
- 📊 **Диагностика**: `browser_performance` возвращает тайминги навигации, первую отрисовку, размеры ресурсов и медленные ресурсы, кучу JS и размер DOM, не открывая DevTools.
- 🌐 **Двуязычный интерфейс**: следует языку системы или браузера либо позволяет закрепить в настройках упрощённый китайский / английский.
- 🔒 **Безопасность по принципу локальности**: WebSocket только на loopback, случайный токен при каждом запуске, белый список сайтов, изолированные вкладки, маскирование сетевых данных и подтверждение в браузере для рискованных операций.
- 📦 **Проверяемые выпуски**: Windows NSIS и Linux AppImage выходят в одной версии с `SHA256SUMS.txt`, неизменяемыми аттестациями релизов GitHub и CycloneDX `sbom.cdx.json`.

## Пример снапшота

Вызов `browser_snapshot` на главной странице Bing возвращает (реальный вывод, приведён дословно):

```text
页面快照 url: https://www.bing.com/
title: 搜索 - Microsoft 必应
元素数: 19

- banner "登录 Rewards 手机版"
  - img "必应"
  - navigation
    - menuitem "图片" [ref=e1]
    - menuitem "视频" [ref=e3]
- search
  - combobox "搜索网页" [ref=e15]
  - button "语音搜索" [ref=e16]
```

Затем агент действует по `ref`:

```jsonc
{ "tool": "browser_type", "arguments": { "ref": "e15", "text": "Aa Browser", "submit": true } }
```

После действия вы получаете **инкрементальный снапшот** — только изменённые блоки и сведения о том, какие `ref` добавлены или аннулированы. `browser_snapshot { full: true }` принудительно возвращает полное дерево.

## Установка

### Одна инструкция (рекомендуется)

Отправьте промпт из [PROMPT.md](../../../PROMPT.md) любому ИИ, который умеет выполнять локальные команды. Если Aa Browser ещё не установлен, он скачает официальный установщик, проверит SHA-256, установит, запустит, запишет конфигурацию MCP и действительно вызовет `browser_tabs` для проверки. Если Aa Browser уже запущен, он только запишет конфигурацию и проверит её.

```bash
node install.mjs --repo yuchen0x1/aa-browser --verify --json   # download, verify, install, connect, verify
node install.mjs --connect-only --verify --json                 # already installed: connect and verify only
node install.mjs --verify-only                                  # verify the browser side, write nothing
node install.mjs --print-config                                 # print a generic MCP config fragment (pure JSON)
```

Установщик никогда не задаёт интерактивных вопросов. `--clients zcode,cursor` ограничивает, какие клиенты настраиваются, `--dir <dir>` переопределяет каталог установки, `--no-launch` пропускает запуск, а `--sha256 <hex>` задаёт ожидаемый хеш установщика. Любой другой MCP-клиент может использовать вывод `--print-config`.

### Windows

Скачайте `aa-browser-setup-<version>.exe` со страницы [GitHub Releases](https://github.com/yuchen0x1/aa-browser/releases/latest) и запустите его. Установщик **не подписан кодом**: когда появится SmartScreen, выберите «Подробнее → Выполнить в любом случае». Каждый выпуск также содержит `SHA256SUMS.txt`, `sbom.cdx.json` и неизменяемую аттестацию релиза, чтобы вы могли проверить файлы сами.

### Linux AppImage

Скачайте `aa-browser-<version>-linux-x86_64.AppImage`, сделайте его исполняемым и запустите из текущей сессии рабочего стола. Нужны GTK 3, NSS, GBM, аудиобиблиотеки и работающая песочница Chromium; для доступа по MCP требуется системный Node.js 22.12 или новее.

```bash
mkdir -p ~/Applications
mv aa-browser-<version>-linux-x86_64.AppImage ~/Applications/AaBrowser.AppImage
chmod u+x ~/Applications/AaBrowser.AppImage
~/Applications/AaBrowser.AppImage
```

Без FUSE запускайте так: `APPIMAGE_EXTRACT_AND_RUN=1 ~/Applications/AaBrowser.AppImage`. Статус по дистрибутивам и шаги восстановления — в [руководстве по платформам](../../../docs/PLATFORMS.md).

### Из исходного кода

Требуется Node.js 22.12 или новее.

```bash
git clone https://github.com/yuchen0x1/aa-browser.git aa-browser
cd aa-browser
npm ci             # downloads Electron on first run
npm run build      # main, preload, renderer, MCP bridge and DeepSeek Harness plugin bridge
npm start          # launch the built app
```

Режим разработки с горячей перезагрузкой рендерера — `npm run dev`; он использует отдельный каталог пользовательских данных `aa-browser-dev`, поэтому может работать одновременно с установленной сборкой.

## Подключение агента

Требования: Aa Browser запущен (он записывает порт и токен в `~/.aabrowser/connection.json`), клиент поддерживает stdio MCP, и оба работают от одного пользователя на одной машине.

- **В один клик**: Настройки → Подключить ИИ-клиент → отметить клиентов → записать. После этого перезапустите клиент.
- **Вручную**: выполните `node install.mjs --print-config` и вставьте выведенные `command` / `args` / `env` в конфигурацию клиента. Существующие конфигурации сохраняются в `<файл>.aa-backup-<метка времени>`; изменяется только запись `aa-browser`, а записи идемпотентны.

### Статус и проверка

| Состояние на панели инструментов | Значение |
| --- | --- |
| Ожидание подключения ИИ | Ни один MCP-мост не подключился: конфигурация отсутствует, клиент не перезапущен или браузер не запущен |
| Ожидание первого вызова ИИ | Мост подключён и аутентифицирован, но ни один вызов инструмента ещё не завершился успешно |
| ИИ подключён ×N | Как минимум один вызов списка `browser_tabs` прошёл успешно; N — число проверенных мостов |

Записанная конфигурация — **не** рабочее подключение. Проверьте с помощью `node install.mjs --verify-only` или дайте агенту действительно вызвать `browser_tabs`.

## Инструменты MCP

**43 инструмента** в пяти группах: навигация и снапшоты (5), взаимодействие (9), чтение и состояние (20), сеть и Mock (6), диагностика и вкладки (3). Имена инструментов в клиенте могут иметь префикс `mcp__aa-browser__`.

| Группа | Инструменты |
| --- | --- |
| Навигация и снапшоты | `browser_navigate`, `browser_snapshot`, `browser_navigate_back`, `browser_navigate_forward` |
| Взаимодействие | `browser_click`, `browser_type`, `browser_fill_form`, `browser_select_option`, `browser_drag`, `browser_hover`, `browser_scroll`, `browser_press_key`, `browser_upload_file` |
| Чтение и состояние | `browser_extract`, `browser_evaluate`, `browser_dialogs`, `browser_wait`, `browser_screenshot`, `browser_find`, `browser_get_selector`, `browser_cookies`, `browser_storage`, `browser_downloads`, `browser_pdf`, `browser_console` |
| Сеть и Mock | `browser_network_requests`, `browser_network_detail`, `browser_har`, `browser_mock_requests`, `browser_list_mocks`, `browser_clear_mocks` |
| Диагностика и вкладки | `browser_performance`, `browser_resize`, `browser_tabs` |

Общее поведение: большинство инструментов возвращают снапшот вместе с результатом (`snapshot: false` пропускает его), каждый инструмент, кроме `browser_resize` и `browser_downloads`, принимает `tabId`, один вызов завершается по тайм-ауту через 180 секунд, подтверждение ожидается до 120 секунд, а сетевые детали по умолчанию маскируются.

## Безопасность

- Служба агента слушает только `127.0.0.1`, использует случайный токен при каждом запуске и отклоняет нелокальные источники; порт и токен хранятся в `~/.aabrowser/connection.json` и удаляются при корректном выходе.
- Представления страниц работают без preload-скрипта; снапшоты и скрипты действий внедряются главным процессом. Навигация разрешает только `http:` / `https:` — протоколы `file:`, `data:`, `devtools:` и подобные отклоняются.
- Чувствительные поля ввода должен заполнять сам пользователь: текст, предоставленный агентом, никогда не записывается, не читается и не возвращается. При включённом параметре «подтверждать рискованные операции» отправка форм, Enter после ввода и доступ к немаскированным сетевым данным ожидают подтверждения в браузере (120 секунд, после чего считаются отклонёнными).
- Сетевые детали и экспорт HAR по умолчанию маскируют заголовки аутентификации и параметры, похожие на учётные данные.
- **Белый список сайтов**: действует только на навигацию; пустое значение отключает его, и даже когда он пуст, протоколы `file:`, `data:`, `devtools:` и другие не-веб-протоколы остаются заблокированными.
- **Подключение агента меняет только одну запись**: существующие конфигурации клиентов сначала сохраняются в резервную копию, изменяется только запись `aa-browser`, token и пароли никогда не записываются, а при скачивании установщика проверяются SHA-256-дайджест релиза и заголовок файла.
- Изолированные вкладки используют отдельный раздел сессии: без общих cookie и сессий входа, очищаются при закрытии и исключаются из глобальной истории, списка недавно закрытых вкладок и восстановления сессии.
- **Граница**: агент может видеть содержимое страниц и трафик, включая cookie, storage, заголовки и тела ответов. Эти меры — смягчение рисков, а не универсальный DLP; не направляйте недоверенного агента на высокочувствительные сайты.

Сообщайте об уязвимостях через приватную форму в [SECURITY.md](../../../SECURITY.md), никогда — в публичном issue.

## Платформы и ограничения

| Платформа | Официальная сборка | Примечания |
| --- | --- | --- |
| Windows 11 x64 | Установщик NSIS | Активно поддерживается, покрыто CI и локальными регрессиями |
| Windows 10 x64 | Тот же установщик | Использует сборку Windows 11; приёмка обновления на реальном устройстве всё ещё ожидается |
| Linux x86_64 (рабочий стол Ubuntu) | AppImage | Нужен системный Node.js 22.12+; другие дистрибутивы требуют проверки на реальном устройстве |
| Windows ARM64 / macOS / Android / iOS | Нет | Установщик явно отказывается, а не делает вид, что устанавливает |

Известные ограничения:

- **Нет подписи кода** в Windows: SmartScreen предупреждает и требует «Подробнее → Выполнить в любом случае».
- **Не замена Chrome**: нет закладок, расширений и синхронизации аккаунта или между устройствами. Область — «ядро браузера + доступ агента».
- **Доступ по MCP в Linux требует системного Node.js 22.12+**; в Windows используется встроенная среда выполнения, если системный Node не найден.
- **Восстановление сессии ограничено**: только обычные веб-вкладки, не более 20 записей, никогда — изолированные вкладки, внутренние страницы и URL не по HTTP(S).
- **Один экземпляр на каталог пользовательских данных**; dev-сборка использует свой каталог, поэтому обе могут работать.
- **Установка и обновления зависят от GitHub Releases**; самообновление AppImage требует каталога с правом записи.
