01 — 问题

别让 Agent 靠猜坐标上网。

截图 → 视觉模型找元素 → 猜像素 → 点击 → 再截图。这条链路每一步都在烧上下文，界面一改就断。网页本来就有结构，Agent 应该直接读它。

截图式自动化
Screenshot loop
截图 → 猜坐标 → 点击 → 再截图 ↺
  • 每一步都要重读整页像素，多步任务上下文很快打满
  • 布局偏移、弹层、响应式变化都会让坐标失效
  • Cookie、Storage、网络请求看不见，登录态问题只能靠猜
成本 = 页面复杂度 × 步数 × 像素
Aa Browser 的快照式驱动
Snapshot loop
DOM → 结构化快照 → ref=e15 → 精确动作 ↺
  • 每个可交互元素带稳定 ref，React 重渲染也能接上
  • 动作后只回差量，页面没变就只回一行
  • 原生抓包 / Cookie / Storage / 性能，全部走同一个协议
成本 = 变化量，而不是页面大小

02 — 能力

像一个真浏览器那样上网，
像一个工程师那样操作。

不是无头容器里的一次性工具。Aa Browser 是你日常能用的浏览器：标签页、地址栏、登录态、下载、书签式会话恢复，全都在。Agent 通过 MCP 接入同一个实例。

01 / Snapshot

结构化快照，而不是截图

DOM 被转换成 YAML 风格的可访问性树，每个可交互元素带 ref 编号。格式对齐 Playwright MCP 生态，现有 Agent 几乎零学习成本。

02 / Input

真实输入路径

点击走受信任的输入事件，输入走 insertText 管线，对 React 受控组件有兜底；被遮挡的元素自动降级为合成事件。

06 — 接入

三分钟，把浏览器
交给你的 Agent。

推荐路径是让 AI 自己完成：它能下载、校验、安装、写配置，并在最后真的调用一次工具。PROMPT.md 里写死了这些约束。

STEP 01

下载并启动 Aa Browser

从 GitHub Releases 取最新 Windows 安装包或 Linux AppImage。安装包未签名，SmartScreen 提示时选择「仍要运行」。

选择平台 直接去 Releases
STEP 02

让 AI 写配置，或手动执行一行命令

把 PROMPT.md 整段发给具备本机命令执行能力的 AI；也可以自己运行安装器。它会备份原配置，只修改 aa-browser 一个条目。

$ node install.mjs --repo yuchen0x1/aa-browser --verify --json
Node.js ≥ 22.12 自动备份配置 幂等可重跑
通用 MCP 配置（任意客户端）

也可以用 node install.mjs --print-config 生成，不要猜测客户端的配置文件路径。

JSON { "mcpServers": { "aa-browser": { "command": "node", "args": ["C:\\Program Files\\aa-browser\\cli\\mcp.mjs"] } } }
STEP 03

用一次真实调用验证

重启 AI 客户端，让它调用 browser_tabs。只有工具实际返回标签列表，工具栏才显示「AI 已连接」；若桥已连上但还没调用成功，会显示「等待 AI 首次调用」。

验证成功 = AI 已连接 配置写入成功 ≠ 已接通
Local by design

权限留在本机，
边界写在代码里。

Agent 能力越强，边界越要清楚。Aa Browser 不中转、不上传、不远程托管；每一个连接都要本机 token，每一次写配置都先备份。

Agent 能看到页面内容与网络流量，包括可能含秘密的 Cookie、Storage、请求头和响应体。敏感输入审批是基于页面字段特征的保护，不是通用 DLP —— 不要让不可信 Agent 访问高敏站点。
仅本机监听

WebSocket 绑定 127.0.0.1，拒绝非本机来源的连接，不暴露到局域网。

随机端口 + 一次性 token

启动时生成随机端口与 token，写入 ~/.aabrowser/connection.json，仅当前用户可读。

写配置前自动备份

备份为 .aa-backup-<时间戳>，只改 aa-browser 一个条目，可重复执行。

站点白名单

每行一条 https://example.com 或通配规则；填写后只允许匹配的 HTTP/HTTPS 导航。

会话隔离

隔离标签使用独立的 Electron session 分区，关闭后清理会话数据。

脱敏与人工审批

网络详情与 HAR 默认脱敏；开启高危确认后，未脱敏导出需用户批准。

Q1它和 Playwright MCP 有什么区别？
快照格式与 ref 交互范式对齐 Playwright MCP，所以 Agent 不用重新学习。但 Aa Browser 是一个完整的桌面浏览器：共享你的登录态、标签页与会话，原生带抓包 / Mock / HAR、Cookie / Storage 与性能诊断，不需要为每个任务启动一个无头实例。
Q2需要会写代码吗？
不需要。安装包双击即用；接入时把 PROMPT.md 交给有本机执行能力的 AI，或在工具栏「设置 → 连接 AI 客户端」里勾选即可。命令行只是给你想自己控制时用的。
Q3支持 macOS 吗？
目前官方发行只覆盖 Windows x64 与 Linux x86_64。安装器遇到 macOS、Windows ARM64 或其他架构会明确拒绝，不会假装安装。你可以从源码自行构建，但那不属于官方验证过的分发渠道。
Q4Agent 能看到我的密码吗？
能读取你允许它操作的页面内容，包括可能含秘密的 Cookie、Storage、请求头和响应体。请配合站点白名单与会话隔离使用，不要把高敏后台交给不可信的 Agent。敏感输入审批与网络脱敏是缓解措施，不是通用 DLP。
Q5为什么工具栏显示「等待 AI 首次调用」？
说明 MCP 桥已经连上，但还没有任何一次工具调用成功。让客户端实际调用 browser_tabs，返回标签列表后状态才会变成「AI 已连接」。配置写入成功本身不代表接通。
Q6收费吗？数据会上传吗？
MIT 开源、免费，没有账号体系，也没有云端中转。浏览器本地直连，更新检查走 GitHub Releases；本站是纯静态页面，不加载追踪脚本或第三方字体。
